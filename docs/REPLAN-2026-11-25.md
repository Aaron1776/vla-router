## 5. Setup count for runs that start fresh (amendment 62 (2)): proposal

**What the survey measured:** a Mac run of tasks 3, 8 and 9, with task 0 as a control, at initial states 0 and 30,
for load counts 2-51.
- In tasks 3, 8 and 9 the fixtures land somewhere new at **every** count. They sit 7-13 mm (median) from where they
  are at count 2, up to 18 mm. Consecutive counts differ by about 8-12 mm: each extra load is a fresh draw within the
  samplers' range.
- Task 0's fixtures never move.
- One setup takes 0.26 s (tasks 3, 8, 9) to 0.67 s (task 0) on the Mac.

| option | the count | warm-up cost | notes |
| --- | --- | --- | --- |
| **(A) a fresh simulator per episode (recommended)** | 2 for every fresh-start run: exploration and DAgger screens, evaluation trunks | none: one simulator build per episode (~0.2-0.7 s); with `max_jobs` 2 most jobs build one already | a re-run, audit or π0.5-alone episode replays it by building a fresh simulator; deterministic, no search |
| (B) LIBERO's evaluation-loop count | i + 2 for initial state i (one simulator per task, episodes in order) | i extra setups, 24.5 on average: ~6-16 s per episode on the Mac (~1-2.4 VM-s at 7 workers), ~$0.6 across both accounts | matches the standard loop's scenes only if its reset behaviour is the one assumed (to be checked) |

**Under (A):**
- Every marker records its setup count (2), and replays check the fixtures against the original's model fields where
  a snapshot exists.
- Base parents are unaffected: branches restore snapshots, which carry their own fixtures.
- **Code before Phase 1:**
  - the marker field;
  - `ProductionEpisodes` building a fresh simulator for each fresh-start episode (restores keep the cache);
  - the replay check in re-runs, audits and π0.5-alone episodes.
